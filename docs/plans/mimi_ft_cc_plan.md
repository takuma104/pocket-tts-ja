# Mimi decoder FT: CC BY のデータだけで作る decoder 実験計画 v1

目的: 学習に使う音声を CC BY のもの（自然音声は YODAS 系だけ）に限っても、`mimi_ft_hf_plan.md` の decoder（H2ghSG4p100E、soup12hp。JVS 再構成 1,000 文の UTMOSv2 hp40 は keep4k +0.396 / +0.397、録音 +0.400）と同程度まで持ってこられるかを確かめる。届けば、main の CC 版（B-CC の生徒 D1-CC / D0-CC、`pocket-tts-ja-cc` 案）と一緒に公開する decoder の候補にする（公開するかどうかはユーザーが決める）。

ユーザーの依頼（2026-10-20）: 「自然音声を CC ライセンスのもの（Yodas 系）のみに絞った場合、同程度までもってこれるか」「Yodas 音声はクリップ毎にクオリティにかなりばらつきがあると思われますので、データ選別が重要になってくるかもしれません」。

## 1. ライセンスの前提

| 使える | 条件 |
|---|---|
| 元の Mimi（kyutai/pocket-tts） | CC BY 4.0。出発点 |
| YODAS3 ja（espnet/yodas3） | CC BY 3.0（引用の指定あり）。YouTube の opus、全帯域の自然音声 |
| Emilia-YODAS | CC BY 4.0。32 / 64kbps で帯域が狭い（高域の学習には使えない） |
| CC の声の Irodori 合成（`data/synth/s3_cc`） | Irodori-TTS v4.1 は MIT、参照の声は Emilia-YODAS（main の監査 `scripts/release/audit_cc_mix.py` で確認済み）。110,885 文 |

使えないもの: Hi-Fi-CAPTAIN（CC BY-NC-SA 4.0）、Emilia の高品質分（`data/m2/emilia_hq`、NC）、`data/synth/s3_full`（NC の声を含む）、JVNV（CC BY-SA 4.0。継承の条件が混ざる）、あみたろ（独自の規約）。

**今の decoder はどれも出発点にできない**。keep4k（`M2_gs2gan_keep4k`）は `M2_gan_spec` → `M2_gan_spec2` → keep4k の続きで、どれも s3_full と Emilia HQ を半々で学習している（`scripts/m2/run_gan_keep.sh`、main の計画 10/17 の記録）。HF の段（`run_hf.sh`）は Hi-Fi-CAPTAIN・JVNV・Emilia HQ で学習し、識別器も keep4k のものから始めている。CC 版は元の Mimi からやり直し、識別器も CC のデータだけで学習する。JVS はこれまでどおり評価だけに使う（学習には使わない）。

## 2. データ: YODAS3 の選別

### 2.1 一段目（メタデータ、済み）

`scripts/m2/extract_yodas3.py --select`。main の TTS の学習に使った YODAS3 の採用分（`data/yodas3_kept/train.jsonl`、238,233 発話 / 600.7h。字幕と Whisper が一致する自然音声で、DNSMOS OVRL 2.9 以上、量産の TTS の声に近いものは除外済み）から、

- 動画の音声が 15kHz 以上まで入っている（メタデータの `max_freq_hz`。opus の low-pass で決まる。採用分の時間で 10% 点 13.5kHz、中央値 20kHz）
- DNSMOS P.835 が OVRL 3.2、SIG 3.5、BAK 3.9 以上

で **90,241 クリップ / 234.4h、話者 7,470 人、動画 6,219 本**（107 シャード）。比較: Hi-Fi-CAPTAIN は女性・男性それぞれ約 1.9 万クリップ（各約 20h）。クリップは動画から切り出し直す（`process_shard.py` が見つけた時刻。48kHz で decode、チャンネル平均、24kHz に soxr で変換）。出力は `data/m2/yodas3/audio`（git 管理外）。

切り出しは 10/20 3:34 に完了（全 90,241 クリップ、失敗 0）。最初の版は動画を丸ごとメモリに展開していて、1 プロセスで最大 6GB、16 プロセスでマシンのメモリが残り 8GB まで減った（Claude Code の待機コマンドがメモリ不足で止められた）。最後のクリップまでしか復号せず、残りのクリップに要る数秒分だけを持つようにして、1 プロセス 0.26GB（2.7 時間の動画）にした。切り出したクリップはサンプル単位で前と一致する。

学習の読み込みは `--max-seconds`（8 秒）より長い行を捨てる。8 秒以下は 45,551 クリップ / 65.7h だけなので、学習用のリストでは長さを 7.99 秒に切り詰めて、長いクリップは先頭 8 秒を使う。

### 2.2 二段目（音声から測る）

切り出した音声で、クリップごとに次を測る（`scripts/m2/score_yodas3.py`。学習と同時で 1 秒に約 16 クリップ、全部で約 1.5 時間）。

| 指標 | 中身 | 狙い |
|---|---|---|
| 帯域 | 有声フレームの 8–12kHz と 11–12kHz のレベル（1–4kHz 比） | 再エンコードやノイズ除去で高域が欠けたクリップを除く |
| 高域の倍音 | 有声フレームの 4–6 / 6–8kHz の comb（`hf_structure.py` と同じ測り方、自分の F0 で） | decoder に学ばせたいもの（倍音のある高域）を持つクリップを選ぶ |
| 性別 | F0 の中央値 | Hi-Fi-CAPTAIN と同じく女性を多めに混ぜる |
| クリッピング | 振幅が上限近くのサンプルの割合 | 歪んだクリップを除く |
| UTMOSv2（hp40） | クリップそのものの予測 MOS | 主な指標と同じ物差しで選ぶ。1 秒に約 3 クリップ（6 workers、最大 7GB）なので、帯域とクリッピングで絞ったプール（約 5 万クリップ）に 4〜5 時間 |

**最初の 9,000 クリップでの分布**: F0 165Hz 以上（女性とみなす）が 53%。女性の 4–6kHz の comb は中央値 3.5dB、上位 1/4 は 4.6dB 以上、上位 1/10 は 5.8dB 以上（`data_harmonicity.py` のフレーム単位の値で Hi-Fi-CAPTAIN 女性 5.5、JVS 女性 5.1、Emilia HQ 4.0）。上位の YODAS3 はスタジオ録音並みの倍音を持つ。

**帯域の基準**: スタジオ録音（各 200 クリップ）の 8–11kHz は 1–4kHz より 14〜17dB 低く（10% 点で −20〜−22dB）、11–12kHz は 8–11kHz より 4〜8dB 低い（10% 点で −8〜−10dB）。YODAS3 は 8–11kHz が中央値 −20dB、10% 点 −41dB、11–12kHz の落ち込みは中央値 −8.6dB、10% 点 −20dB（11kHz 付近で切れているクリップ）。プールの条件は、有声フレーム 20 以上、8–11kHz −30dB 以上、11–12kHz の落ち込み −12dB 以内、クリッピング（0.99 以上のサンプル）1e-4 以下。最初の 9,000 クリップでは 56% が残る（帯域で 36%、クリッピングで 6% 落ちる）。

残響と BGM は DNSMOS の BAK と UTMOSv2 に任せる。選んだあと 50 クリップ程度を試聴ページにして、外れ（BGM、強い残響、ノイズ除去の跡、合成音声）を目で見て確かめる。

### 2.3 HF の段に使う組み合わせ

`scripts/m2/select_yodas3.py`。女性と男性を分けて `--data` に渡す（`run_hf.sh` の `DATA=`）。比率は女性 0.55、男性 0.45（元の HF の段は Hi-Fi-CAPTAIN 女性 0.45、男性 0.35、JVNV 0.1、Emilia HQ 0.1）。候補:

- **Y-all**: 二段目の帯域とクリッピングだけで除いた全体（選別の効果を見る対照）
- **Y-hf**: 4–6kHz と 6–8kHz の comb の和の上位（性別ごとに 1 万クリップ）
- **Y-mos**: UTMOSv2 の上位（性別ごとに 1 万クリップ）

量は性別ごとに 20〜40h を目安にする（Hi-Fi-CAPTAIN と同程度以上。話者は数千人になる）。

## 3. 実験

### C1: HF の段のデータだけを替える（出発点 keep4k、診断用）

H2ghSG4p100E のレシピ（`run_hf.sh` に `--w-high 15 --w-adv 4 --w-fm 40 --w-spec 100 --ema 0.9997` など、10k step、1 本約 1.3 時間）で、Hi-Fi-CAPTAIN・JVNV・Emilia HQ を YODAS3 の組み合わせに替える。出発点と識別器は keep4k のままなので公開はできないが、データの選び方の比較が速く回せる。p100E（+0.396）との同じ文の差（`mos_pair.py`）で見る。選び方をここで決める。

run 名は `M2Y_hf`、`M2Y_all`、`M2Y_mos`（`runs/lane_c1.sh`。GPU のメモリのため 1 本ずつ、C2 と UTMOSv2 の採点と並行）。

**M2Y_hf の結果（10/20 5:38）**: p100E に大きく届かない。

| 再構成 | UTMOSv2 Δkeep4k（女性） | UTMOS22 Δkeep4k | Kana-CER | 類似度 | ViSQOL |
|---|---:|---:|---:|---:|---:|
| 録音 | +0.400（+0.530） | +0.081 | 3.34% | – | – |
| p100E | +0.396 | | 4.73% | 0.788 | 3.916 |
| M2Y_hf_5k | +0.182（+0.272） | −0.015 | 4.63% | 0.809 | 3.859 |
| M2Y_hf | +0.209（+0.310） | −0.072 | 4.59% | 0.818 | 3.983 |

- 同じ文での差（`mos_pair.py`）は p100E に対して UTMOSv2 −0.187 ± 0.005（女性 −0.182）、UTMOS22 −0.063 ± 0.003。
- 録音との近さはむしろ良い。類似度 0.818、ViSQOL 3.983、NSIM は 4–8k 0.780、8–12k 0.759 で、どれも H2gh 以上。高域の倍音（`hf_structure.py`、女性の 4–6k comb 1.9dB）と帯域ごとのレベル（4–10kHz で録音の −1.3〜−1.9dB）も p100E と同じ。予測 MOS だけが低い。HF の段のデータ配分で見た傾向（元の配分は類似度が高く UTMOSv2 が低い、スタジオ中心はその逆）が、もっと強く出ている。

**学習データそのものの予測 MOS**（hp40、各 1,000 クリップ、`exp/m2/refmos`。YODAS3 はプール全体）:

| データ | UTMOSv2 平均 | UTMOS22 平均 |
|---|---:|---:|
| Hi-Fi-CAPTAIN 女性 | 3.259 | 3.467 |
| Hi-Fi-CAPTAIN 男性 | 3.595 | 3.696 |
| Emilia HQ | 3.255 | 3.284 |
| JVNV | 2.976 | 2.005 |
| Irodori s3_cc（合成） | 3.230 | 2.831 |
| YODAS3 女性（プール 28,193） | 3.089 | 2.701 |
| YODAS3 男性（採点途中 11,826） | 3.110 | 2.715 |

- 配分ごとの UTMOSv2 の重み付き平均は、スタジオ中心（SG）3.348、女性寄り（FG）3.297、中間（MG）3.314、元の配分（G）3.279。HF の段の UTMOSv2 は SG4 +0.364、FG4 +0.348、MG4 +0.331、G4 +0.300 で、ほぼ同じ順に並ぶ。学習データの予測 MOS が decoder の出力の予測 MOS を決めている、と見てよさそう。
- YODAS3 は UTMOS22 で 0.6〜1.0 低い。YODAS3 の中では、倍音の強さと UTMOSv2 の順位相関は −0.02（倍音で選んだ hf の UTMOSv2 は全体と同じ）。UTMOSv2 と相関があるのは DNSMOS OVRL（0.28）と音量（0.22）くらい。UTMOSv2 のばらつきの 7 割は話者（収録環境）の間の違い。UTMOSv2 と UTMOS22 の順位相関は 0.55。
- そこで、UTMOS で選ぶ組み合わせを 2 つにする。
  - **mos**: UTMOSv2 の上位、性別ごとに 1 万クリップ（女性で UTMOSv2 3.457 / UTMOS22 3.070）。
  - **mz5**: UTMOSv2 と UTMOS22 の z-score の和の上位、性別ごとに 5,000 クリップで 1 話者 150 まで（女性で 3.473 / 3.552、8.2h、808 話者）。
  - run は `M2Y_mos` と `M2Y_mz5`（`runs/lane_c1b.sh`）。上位を集めた試聴ページ `exp/listening/y3_sets2` も作り、合成音声や BGM が混ざっていないかを耳で確かめる（mz5 の女性は 21% が UTMOS22 4 以上で、合成音声が混ざっていないかが気になる。ページにはクリップの多い 8 話者の段も置いた）。

**C1 の結果**（p100E との同じ文の差。UTMOSv2 のカッコは女性）:

| run | 学習データ（女性の UTMOSv2 / UTMOS22） | UTMOSv2 Δkeep4k | p100E との差 UTMOSv2 | UTMOS22 | Kana-CER | 類似度 | ViSQOL |
|---|---|---:|---:|---:|---:|---:|---:|
| M2Y_all | プール全体（3.09 / 2.70） | +0.199（+0.287） | −0.197 ± 0.005（−0.206） | −0.054 | 4.56% | 0.818 | 3.982 |
| M2Y_hf | 倍音の上位（3.08 / –） | +0.209（+0.310） | −0.187 ± 0.005（−0.182） | −0.063 | 4.59% | 0.818 | 3.983 |
| M2Y_mos_5k | UTMOSv2 の上位（3.46 / 3.07） | +0.235（+0.325） | −0.161 ± 0.005（−0.167） | +0.008 | | | |
| M2Y_mos | 同 | +0.265（+0.375） | −0.131 ± 0.005（−0.118） | −0.033 | 4.61% | 0.815 | 3.990 |
| M2Y_mz5_5k | UTMOSv2 + UTMOS22 の上位（3.47 / 3.55） | +0.218（+0.298） | −0.178 ± 0.005（−0.195） | +0.023 | | | |
| M2Y_mz5 | 同 | +0.257（+0.350） | −0.139 ± 0.005（−0.142） | −0.013 | 4.63% | 0.816 | 3.992 |
| （p100E_5k） | Hi-Fi-CAPTAIN 中心（3.35 / 3.38） | +0.283（+0.357） | | | | | |

- 倍音で選んでも効かない（hf と all の差 0.010）。UTMOSv2 で選ぶと +0.066 上がる。ただし学習データの UTMOSv2 は mos（3.46 / 男性 3.43）のほうがスタジオ中心の配分（3.35）より高いのに、出力はまだ 0.13 低い。UTMOSv2 だけでは説明しきれない。残る違いは、学習データの UTMOS22（mos 3.04、スタジオ中心 3.38）と、収録環境の数（Hi-Fi-CAPTAIN は 2 話者、YODAS3 は数千の動画）。mz5 は前者を確かめる。
- どの run も録音との近さ（類似度、ViSQOL、NSIM 8–12k 0.762）は p100E より良い。
- **mz5（UTMOS22 でも選ぶ）は mos と同じ**: mos との同じ文の差は UTMOSv2 −0.008 ± 0.003（女性 −0.025）、UTMOS22 +0.020。学習データの UTMOS22 を上げても出力の UTMOSv2 は上がらず、UTMOS22 が少し戻るだけ。
- **後半の伸びが違う**: p100E は 5k → 10k で +0.283 → +0.396（+0.113）なのに、YODAS3 の run は +0.03〜0.04 しか伸びない（mos +0.235 → +0.265）。5k の時点の差は 0.05 だけ。
- 差は JVS の 10 話者すべてに出る（話者ごとに −0.07〜−0.21、録音の UTMOSv2 とは無相関）。
- 休止のノイズフロア（最も静かな 10% のフレームの帯域レベル、大きい半分のフレーム比）は、出力では p100E と YODAS3 の run の差が 1–4kHz で約 2dB、4–8kHz で約 1dB（YODAS3 の run が高い）と小さい。学習データでは YODAS3 が Hi-Fi-CAPTAIN より 5〜10dB 高いが、クリップが発話の境目で切られていて休止が短いので、そのままは比べられない。
- C3 のデータは **mos** にする（主な指標の UTMOSv2、とくに女性で mz5 より良く、量も倍）。

### C2: CC の土台（元の Mimi から）

keep4k までの道のりを CC のデータでなぞる。

1. 元の Mimi から 60k step（`M2_gan_spec` の設定: mel + MPD / MS-STFT 識別器 + 共有スペクトル loss。帯域は最初から 300Hz〜12kHz、つまり `M2_gan_spec2` の修正込み）。データは s3_cc 0.5 + YODAS3（二段目の帯域で除いた全体）0.5。元の連鎖の s3_full 0.5 + Emilia HQ 0.5 に対応する。
2. 続けて 10k step、4kHz 以上を元の Mimi の出力に保つ（`run_gan_keep.sh` の設定）。keep4k に対応する。

`scripts/m2/run_cc_base.sh M2C_base`（1 は `runs/M2C_base_gs`、2 は `runs/M2C_base`）。10/20 3:34 開始。データは s3_cc 78,342 クリップ / 115.8h（8 秒以下）、YODAS3 89,785 クリップ / 164.1h（先頭 8 秒）。

keep4k と比べる: 再構成の Kana-CER（keep4k 4.70%）、録音との類似度（0.779）、UTMOSv2 / UTMOS22。元の連鎖の各段の数値（gan60k 4.43% / 0.827 など）とも並べる。学習は 1 本で 4〜5 時間。

### C3: CC の土台 + HF の段

C2 の decoder と識別器から、C1 で決めたデータで HF の段を回す。遅い EMA の 2 本（p100E と p50E、`--w-spec 100` / `50`）と、その平均（soupE2 と同じ。NC 版では +0.399 で soup12hp と同じ水準）。soup12hp のような 4 本 × 3 時点の平均より、学習が半分で済む。

比べる相手: p100E、soup12hp。指標: JVS 再構成の UTMOSv2 / UTMOS22（hp40）、Kana-CER、類似度、ViSQOL の 8–12kHz、TTS の出力（公開中の生徒 D1b 120k に加えて、CC 版の生徒 D1-CC があればそれでも）。試聴ページ（録音 / keep4k / soup12hp / CC 版）。

## 4. 判断の目安

- C1: YODAS3 の組み合わせで p100E との差が −0.02 以内なら、データの選別で足りている。
- C3: soup12hp との差が UTMOSv2 で −0.02 以内、UTMOS22 が keep4k −0.02 以上、Kana-CER 4.9% 以下、類似度 0.76 以上。最後はユーザーの試聴で決める。
- C1 で大きく足りない場合: 選別を強める（量を減らして質を上げる）、Emilia-YODAS や合成音声を 4kHz 以下だけに使う、などを検討する。
