# Mimi decoder FT: 高域の倍音 実験計画 v1

作成: 2026-10-15（JST）。[idea_mimi_ft.md](idea_mimi_ft.md) の案をもとに、このマシンで行った事前検証の結果を入れて実験の順序を組み直した。既存実験の記録は [ja_finetune_plan.md](ja_finetune_plan.md) の M2 の行。

目的は idea_mimi_ft.md と同じ: 採用版 `M2_gs2gan_keep4k`（以下 keep4k）の明瞭度と自然さを保ったまま、女性の有声区間の 4kHz 以上を、雑音ではなく倍音として出す。

## 0. 要約

**事前検証で分かったこと（§2）**

1. **倍音は 4〜4.5kHz を境に急に消える。** 元の Mimi と FT 済みの decoder（gs2_80k、keep4k）に共通で、男女とも同じ周波数で落ちる（倍音の番号ではなく周波数で決まっている）。出力自身の F0 で測っても同じ。4kHz 以下では録音と同じ程度の倍音がある。
2. **ピッチのずれは原因ではない。** decoder の出力の F0 と録音の F0 の差は中央値 3.6〜3.9 cents（女性）。高域の倍音は「ずれて」いるのではなく「無い」。
3. **学習データには 4〜6kHz の倍音がある。** Emilia HQ（高い声のフレーム）で comb 4.0dB（JVS 女性 5.1dB）。6〜8kHz は、あみたろ以外の学習用データで弱い（1.0〜1.9dB、JVS 3.1dB）。Irodori の合成音声（代わりに測ったもの）は 4〜6kHz が同じ話者の実音声より 4dB 暗く、倍音も弱い。
4. **今の decoder の構造のままでも、4kHz 以上に倍音を作れる。** 1 話者 23 クリップへの過学習で、倍音を見る loss（細かい分解能の STFT）を高域にかけると、4〜5kHz の comb は 3.1 → 5.5dB（録音 6.7dB）。**残差層 1 と 3 で到達点は同じ**。同じクリップで高域を mel loss にすると、レベルは上がるが未学習のクリップでは倍音が減る（gs2_80k と同じ現象）。

**これを受けた方針**

- idea_mimi_ft.md は残差層 1 → 3（案 A）を最初の実験にしていた。過学習の結果から、**容量は今のところ律速ではない**と見て、最初は **構造を変えずに高域の学習目標（loss）とデータを変える**（Phase 1）。
- 案 A は Phase 1 で良い学習条件が見つかった後に、同じ条件の対照を付けて 1 本で確かめる（Phase 2）。
- 全データで学習しても未知の話者（JVS）に倍音が出ない場合に、倍音の手がかりを持つ decoder（案 B、Wavehax 系）へ進む（Phase 3）。
- データと識別器の比較（案 C）は、Phase 1 の最良条件に対して一つずつ行う（Phase 4）。
- 採否は従来どおりユーザーの試聴で決める。数値は試聴に回す候補を選ぶために使う。

## 2. 事前検証の結果（2026-10-15）

### 2.1 倍音が消える周波数

JVS 再構成（10 話者 × 6 文）の有声フレームで、出力自身の F0 で測った comb（倍音の位置と中間の位置のレベル差、dB。雑音なら 0）。F0 は 1〜2.5kHz の comb で求め、それより上の帯域で測る（`hf_structure.py --own-f0`。F0 を求める帯域と測る帯域を分けないと、スペクトルの凹凸が大きい出力ほど有利になる）。

| 女性 | 2.5–3k | 3–3.5k | 3.5–4k | 4–4.5k | 4.5–5k | 5–6k | 6–8k |
|---|---:|---:|---:|---:|---:|---:|---:|
| 録音 | 5.8 | 5.1 | 5.1 | 3.3 | 2.0 | 2.4 | 2.1 |
| 元の Mimi | 6.6 | 6.2 | 4.7 | 2.1 | 0.0 | −0.5 | 0.1 |
| gs2_80k | 6.4 | 5.4 | 3.8 | 1.6 | 1.0 | −0.2 | 0.3 |
| keep4k | 6.3 | 5.2 | 4.0 | 2.5 | 0.2 | −0.4 | 0.1 |

| 男性 | 2.5–3k | 3–3.5k | 3.5–4k | 4–4.5k | 4.5–5k | 5–6k | 6–8k |
|---|---:|---:|---:|---:|---:|---:|---:|
| 録音 | 9.8 | 7.7 | 4.7 | 3.8 | 1.9 | 1.9 | 1.5 |
| 元の Mimi | 9.2 | 5.8 | 4.2 | 0.9 | −0.1 | −0.8 | 0.1 |
| keep4k | 8.7 | 5.1 | 3.7 | 1.2 | 0.2 | −0.6 | 0.1 |

- 4kHz までは録音と同じ程度。4〜4.5kHz で減り（録音に対して女性 5〜8 割、男性 2〜3 割）、4.5kHz から上で 0 になる。男女で倍音の間隔は 2 倍違うのに、落ちる周波数は同じ。
- 窓を 43ms（FFT 1024）にすると、録音の 4–6kHz（女性、録音の F0）は 4.7 → 6.3dB に上がるが、decoder は 0.8〜1.6dB のまま。窓の中でのピッチの揺れで倍音がぼやけているのではない。
- 元の Mimi が最初から持つ性質で、これまでの FT（mel、識別器、共有スペクトル loss）はどれもこの境目を動かしていない。

### 2.2 ピッチのずれ

1kHz 以下の自己相関で求めた F0 を、出力と録音で同じフレームどうし比べた。

| | 女性: 中央値 | 90% 点 | 1% 超 | 男性: 中央値 | 90% 点 | 1% 超 |
|---|---:|---:|---:|---:|---:|---:|
| 元の Mimi | 3.9 cents | 14.3 | 7.0% | 2.7 | 10.2 | 2.6% |
| gs2_80k | 3.6 | 13.3 | 5.4% | 2.6 | 9.2 | 2.4% |
| keep4k | 3.6 | 13.3 | 4.8% | 2.5 | 9.1 | 2.4% |

5kHz 付近（女性で 20 倍音前後）でも、中央値のずれは倍音の間隔の 4% ほど。録音に合わせる細かい分解能の loss が、ピッチのずれのせいで倍音を罰する状況ではない。

メモ: 最初の版の `--own-f0` は F0 を 1〜4kHz の comb が最大になるように選び、同じ帯域で測っていた。そのため 1〜4kHz の値が水増しされ、ピッチのずれも 12 cents と過大に出ていた。今の版で直してある。

### 2.3 学習データの高域の倍音

`scripts/m2/data_harmonicity.py`。各ソースから 150 クリップ（Emilia は 450）を取り、そのクリップ自身の有声フレームで comb と、1〜2.5kHz に対する帯域のレベルを測った。F0 が 165Hz 以上のフレーム（女性と高い声の男性）:

| ソース | フレーム | 4–6k comb | 6–8k comb | 4–6k レベル | 6–8k レベル |
|---|---:|---:|---:|---:|---:|
| JVS 女性（評価用） | 13,540 | 5.1 | 3.1 | −11.8 | −14.5 |
| Emilia HQ | 20,639 | 4.0 | 1.1 | −12.8 | −16.4 |
| Hi-Fi-CAPTAIN 女性 | 9,478 | 5.5 | 1.0 | −14.9 | −20.3 |
| JSUT（参考） | 7,858 | 4.4 | 1.2 | −11.4 | −13.5 |
| JVNV | 12,044 | 4.6 | 1.9 | −14.0 | −17.6 |
| あみたろ | 7,528 | 6.3 | 2.8 | −16.5 | −15.4 |
| JVS jvs001（男性、実音声） | 5,458 | 3.0 | 2.4 | −20.0 | −19.7 |
| Irodori（jvs001 を参照に合成） | 2,865 | 2.0 | 1.5 | −23.8 | −21.5 |

- 4〜6kHz の倍音は、どの自然音声のデータにも JVS のおよそ 8 割以上ある（Emilia HQ 78%、ほかは 9 割以上）。**採用版の学習データ（S3 + Emilia）に倍音が無かったから出せない、とは言えない**（S3 の半分は弱い可能性がある）。
- 6〜8kHz はあみたろ以外どれも弱い。JVS がむしろ強い側。6〜8kHz の倍音はデータの面でも難しい目標で、主目標は 4〜6kHz に置く。
- Irodori の合成（S3 と同じ系統）は、同じ話者の実音声より 4〜6kHz が約 4dB 暗く（6〜8kHz は 2dB）、倍音も 2/3。S3 の音声そのものは測れていない（galleria2 にある）。

### 2.4 過学習プローブ: 今の構造で 4kHz 以上に倍音を作れるか

`scripts/m2/overfit_probe.py`。keep4k から、Hi-Fi-CAPTAIN 女性の 23 クリップ（2.5〜4.5 秒）だけを 4,000 step 学習（batch 8、LR 1e-4、識別器なし、1 本 3 分）。4kHz 以下は録音に対する mel、4kHz 以上は下の表の loss。評価は学習したクリップと、同じ話者の dev の 20 クリップ。録音の F0 で測った comb / 録音に対するレベル（dB）:

| | 学習 4–5k | 学習 5–6k | 未学習 4–5k | 未学習 5–6k |
|---|---:|---:|---:|---:|
| 録音 | 6.7 | 4.4 | 5.3 | 3.5 |
| 開始時（keep4k） | 3.1 / −6.8 | 1.2 / −6.6 | 2.5 / −6.7 | 0.4 / −6.1 |
| 残差層 1、高域は細かい STFT loss | 5.5 / −1.2 | 3.6 / −1.1 | 2.2 / −1.4 | 1.7 / −1.3 |
| 残差層 3、同上 | 5.6 / −1.1 | 3.5 / −1.1 | 2.4 / −1.2 | 1.8 / −1.0 |
| 残差層 1、高域は mel loss | 4.3 / −0.3 | 2.8 / −0.9 | **1.1** / −0.7 | 1.3 / −1.1 |

- 細かい分解能の STFT loss（`codec_ft.FineSpectrumLoss`）では、学習したクリップの 4〜6kHz に録音の 8 割の倍音が出る。**今の decoder の構造は 4kHz 以上の倍音を表現できる**。
- **残差層 3 は 1 と同じ到達点**（1,000 step 時点で少し速いだけ）。追加した 0.35M パラメータ（SEANet decoder 3.97M の 9%）は効いていない。
- 高域を mel loss にすると、レベルは録音まで上がるが、未学習のクリップの 4〜5kHz は 2.5 → 1.1dB に下がる。mel の帯域は高域で数百 Hz 幅で、倍音か雑音かを区別しないため、雑音で埋まる。gs2_80k と同じ現象を小さな規模で再現した。
- 細かい STFT loss でも、未学習のクリップでは 4〜5kHz が横ばい、5〜6kHz が 0.4 → 1.7dB。23 クリップでは汎化は限られる。全データで未知の話者にどこまで出るかは、まだ分からない（Phase 1 で調べる）。
- 4kHz 以下は、どの条件でも未学習のクリップで悪くなる（過学習のため。この試験の目的外）。

### 2.5 まとめ: 分かったこと / 分かっていないこと

分かったこと:

- 4kHz 以上の倍音が無いのは、ピッチのずれでも、学習データ（少なくとも 4〜6kHz の Emilia）でも、decoder の容量でもなく、**学習の目標が倍音を要求していない**ことで説明がつく。これまでの FT は高域を mel（倍音を見ない）か元の Mimi の出力（倍音が無い）に合わせていた。
- 既存の `M2_fine4k`（元の Mimi から、S3 + Emilia で 10k step、高域は細かい STFT loss、識別器なし）は、レベルが −3.8dB まで戻ったが試聴で悪化と判断された。comb は記録に無い（run は galleria2 にある）。今回の計画は、出発点（keep4k）、データ（自然音声のみ）、識別器、測る指標がそれと違う。

分かっていないこと:

- 全データの学習で、未知の話者（JVS）に倍音が出るか。
- 倍音を出した高域が、試聴で自然に聞こえるか（gs2_80k は数値が良くても不採用だった）。
- latent に、フレームごとの高域の倍音と雑音の比（息漏れの量など）の情報があるか。無ければ平均的な比でしか出せない。

## 4. Phase 1: 構造はそのまま、高域の学習目標を変える

一つずつ変えた 3 本。どれも keep4k から D-nat で 10k step。

| run | 4kHz 以下 | 4kHz 以上 | 識別器が見る帯域 | 共有スペクトル loss | H0 からの変更 |
|---|---|---|---|---|---|
| **H0**（対照） | 録音に対する mel | 元の Mimi の出力に対する mel（採用版と同じ） | 4kHz 以下 | 300–4000Hz | なし。新しいデータと識別器だけの効果を見る（keep4k とほぼ同じになるはず） |
| **H1** | 同上 | 録音に対する細かい STFT loss（`--high-mode fine`） | 4kHz 以下 | 300–4000Hz | 高域の目標 |
| **H2** | 同上 | 同上 | 全帯域 | 300–12000Hz | H1 に、識別器が高域も見る |

- H1 は過学習プローブの条件を全データにしたもの。H2 は、gs2_80k（全帯域の識別器 + 高域 mel）が雑音で埋めた条件と、高域の loss だけが違う。
- 1 本あたり 40〜50 分（GPU を専有）、評価に 20 分ほど。3 本で半日。

**Phase 1 の後の判断**

| 結果 | 次 |
|---|---|
| H1 / H2 の JVS 女性 4–6kHz の comb が目安まで上がり、明瞭度・線スペクトルに退行がない | 試聴ページ → ユーザーの試聴。良ければ Phase 2 |
| comb は上がったが試聴で不自然 | 以前と同じ入れ替えの試聴ページ（低域 / 高域、境目 4kHz）で、どの帯域の何が気になるかを切り分ける。高域の loss の重み、レベルの目標（録音か、元の Mimi + α dB か）を調整 |
| レベルだけ上がり comb が上がらない（雑音で埋まる） | gs2_80k と同じ失敗。loss の調整より Phase 3（倍音の手がかり）へ |
| JVS では comb が上がらない（学習データでは上がる） | 汎化の問題。Phase 3 の latent プローブで、高域の情報が latent にあるかを調べる |

## 5. Phase 2: 容量（案 A）を同じ条件で比べる

Phase 1 の最良の条件で、残差層 1 と 3 を同じデータ・step・seed で比べる（1 本追加）。

- 残差層の追加は `codec_ft.expand_residual_layers`（追加した残差ブロックの最後の畳み込みをゼロにして恒等写像から始める）。確認済み: 追加直後の出力は追加前とビット単位で一致、フレームごとのストリーミング復号と一括復号の差は 1e-4（追加前と同じ水準）、保存と読み直しで一致。`load_decoder` はファイルの残差層の数に合わせて自動で拡張する。
- 過学習プローブでは差が無かったので、全データでも差が無ければ案 A はここで閉じる。差がある場合だけ、幅（`n_filters` 64 → 96、重みの移植が必要）を次の候補にする。
- 公開する場合の注意: 公式の loader は yaml の `seanet.n_residual_layers` を encoder と decoder の両方に使う。encoder にも恒等の残差ブロックを入れ、encode 結果が一致することを確かめてから配布物を作る。CPU 推論速度も測る。

Phase 1 で良い条件が見つかった場合は、この比較と並行して、学習の延長（30k〜50k step）と TTS での確認を行う。

## 6. Phase 3: 倍音の手がかりを持つ decoder（案 B、研究）

Phase 1 で JVS に倍音が出ない場合に進む。推論コードの変更を伴い、公式 wheel にはそのまま載らない。

1. **latent プローブ（B0）**: 32 次元・12.5Hz の latent（前後の文脈つき）から、200Hz 刻みの F0、有声 / 無声、4kHz 以上の倍音と雑音の比を予測する小さなネットを Emilia HQ で学習し、JVS で測る。F0 は今の decoder がすでに中央値 4 cents で再現しているので、焦点は倍音と雑音の比。
2. **正弦波の励振を足す（B1）**: F0 から作った倍音の正弦波（Nyquist を超える倍音は作らない）を、24kHz の段の入力に学習可能な 1×1 畳み込み（ゼロ初期化）で足す。NSF 系の最小の変更で、残りの構造と重みはそのまま使え、位相を累積するだけなのでストリーミングにも載る。**原音の F0 を与える診断版**を先に作り、効果があれば decoder の内部特徴から F0 を予測する版に進む。
3. **Wavehax / Vocos 系（B2）**: 複素スペクトログラムを生成して iSTFT で戻す方式。B1 で足りない場合だけ。

## 7. Phase 4: データと識別器（案 C）

Phase 1 の最良の条件に対して、一つずつ変える。

- **データ**: D-nat と Emilia HQ のみを比べる。6〜8kHz を狙うなら、倍音の強いあみたろの比率を変えた条件も候補（1 話者に偏る点に注意）。
- **識別器**: 全帯域の MS-STFT 識別器と、DAC 系の帯域別 multi-band multi-scale STFT 識別器を比べる。STFT の大きさを 2 の累乗の組み合わせ以外にする案（m2_idea.md の Stability AI の報告）も、線スペクトルが再発した場合の候補。

## 9. ユーザーに決めてもらうこと

1. **順序の変更**: idea_mimi_ft.md の「最初に残差層 1 → 3」をやめ、Phase 1（loss）を先に行ってよいか。
2. **スタジオ録音の扱い**: Hi-Fi-CAPTAIN / JVNV / あみたろは研究の run に使う。公開する decoder に使えるかは、それぞれの利用条件の確認が要る（JSUT は商用利用に連絡が必要なので学習に使わない）。公開を考える段階で決める。
