# Mimi decoder FT: 高域の倍音 実験計画 v1

作成: 2026-10-15（JST）。[idea_mimi_ft.md](idea_mimi_ft.md) の案をもとに、このマシンで行った事前検証の結果を入れて実験の順序を組み直した。既存実験の記録は [ja_finetune_plan.md](ja_finetune_plan.md) の M2 の行。

目的は idea_mimi_ft.md と同じ: 採用版 `M2_gs2gan_keep4k`（以下 keep4k）の明瞭度と自然さを保ったまま、女性の有声区間の 4kHz 以上を、雑音ではなく倍音として出す。

## 0. 要約

**事前検証で分かったこと（§2）**

1. **倍音は 4〜4.5kHz を境に急に消える。** 元の Mimi と FT 済みの decoder（gs2_80k、keep4k）に共通で、男女とも同じ周波数で落ちる（倍音の番号ではなく周波数で決まっている）。出力自身の F0 で測っても同じ。4kHz 以下では録音と同じ程度の倍音がある。
2. **ピッチのずれは原因ではない。** decoder の出力の F0 と録音の F0 の差は中央値 3.6〜3.9 cents（女性）。高域の倍音は「ずれて」いるのではなく「無い」。
3. **学習データには 4〜6kHz の倍音がある。** Emilia HQ（高い声のフレーム）で comb 4.0dB（JVS 女性 5.1dB）。6〜8kHz は、あみたろ以外の学習用データで弱い（1.0〜1.9dB、JVS 3.1dB）。Irodori の合成音声（代わりに測ったもの）は 4〜6kHz が同じ話者の実音声より 4dB 暗く、倍音も弱い。
4. **今の decoder の構造のままでも、4kHz 以上に倍音を作れる。** 1 話者 23 クリップへの過学習で、倍音を見る loss（細かい分解能の STFT）を高域にかけると、4〜5kHz の comb は 3.1 → 5.5dB（録音 6.7dB）。**残差層 1 と 3 で到達点は同じ**。同じクリップで高域を mel loss にすると、レベルは上がるが未学習のクリップでは倍音が減る（gs2_80k と同じ現象）。
5. **ただし全データで同じ loss をかけた既存の `M2_fine4k` は、JVS に倍音を出していない**（4–6kHz 0.7dB、レベル −3.8dB）。少数のクリップなら作れるが、多くの話者・文に汎化していない。

**これを受けた方針**

- idea_mimi_ft.md は残差層 1 → 3（案 A）を最初の実験にしていた。過学習の結果から、**容量は今のところ律速ではない**と見て、最初は **構造を変えずに高域の学習目標（loss）とデータを変える**（Phase 1）。`M2_fine4k` との違い（出発点、自然音声のみのデータ、識別器）で汎化するかを見る。
- 案 A は Phase 1 で良い学習条件が見つかった後に、同じ条件の対照を付けて 1 本で確かめる（Phase 2）。
- 全データで学習しても未知の話者（JVS）に倍音が出ない場合に、倍音の手がかりを持つ decoder（案 B、Wavehax 系）へ進む（Phase 3）。
- データと識別器の比較（案 C）は、Phase 1 の最良条件に対して一つずつ行う（Phase 4）。
- 採否は従来どおりユーザーの試聴で決める。数値は試聴に回す候補を選ぶために使う。

## 2. 事前検証の結果（2026-10-15）

### 2.1 倍音が消える周波数

JVS 再構成（10 話者 × 6 文）の有声フレームで、出力自身の F0 で測った comb（倍音の位置と中間の位置のレベル差、dB。雑音なら 0）。F0 は 1〜2.5kHz の comb で求め、それより上の帯域で測る（`hf_structure.py --own-f0`。F0 を求める帯域と測る帯域を分けないと、スペクトルの凹凸が大きい出力ほど有利になる）。

| 女性 | 2.5–3k | 3–3.5k | 3.5–4k | 4–4.5k | 4.5–5k | 5–6k | 6–8k |
|---|---:|---:|---:|---:|---:|---:|---:|
| 録音 | 5.8 | 5.1 | 5.1 | 3.3 | 2.0 | 2.4 | 2.1 |
| 元の Mimi | 6.6 | 6.2 | 4.7 | 2.1 | 0.0 | −0.5 | 0.1 |
| gs2_80k | 6.4 | 5.4 | 3.8 | 1.6 | 1.0 | −0.2 | 0.3 |
| keep4k | 6.3 | 5.2 | 4.0 | 2.5 | 0.2 | −0.4 | 0.1 |

| 男性 | 2.5–3k | 3–3.5k | 3.5–4k | 4–4.5k | 4.5–5k | 5–6k | 6–8k |
|---|---:|---:|---:|---:|---:|---:|---:|
| 録音 | 9.8 | 7.7 | 4.7 | 3.8 | 1.9 | 1.9 | 1.5 |
| 元の Mimi | 9.2 | 5.8 | 4.2 | 0.9 | −0.1 | −0.8 | 0.1 |
| keep4k | 8.7 | 5.1 | 3.7 | 1.2 | 0.2 | −0.6 | 0.1 |

- 4kHz までは録音と同じ程度。4〜4.5kHz で減り（録音に対して女性 5〜8 割、男性 2〜3 割）、4.5kHz から上で 0 になる。男女で倍音の間隔は 2 倍違うのに、落ちる周波数は同じ。
- 窓を 43ms（FFT 1024）にすると、録音の 4–6kHz（女性、録音の F0）は 4.7 → 6.3dB に上がるが、decoder は 0.8〜1.6dB のまま。窓の中でのピッチの揺れで倍音がぼやけているのではない。
- 元の Mimi が最初から持つ性質で、これまでの FT（mel、識別器、共有スペクトル loss）はどれもこの境目を動かしていない。

### 2.2 ピッチのずれ

1kHz 以下の自己相関で求めた F0 を、出力と録音で同じフレームどうし比べた。

| | 女性: 中央値 | 90% 点 | 1% 超 | 男性: 中央値 | 90% 点 | 1% 超 |
|---|---:|---:|---:|---:|---:|---:|
| 元の Mimi | 3.9 cents | 14.3 | 7.0% | 2.7 | 10.2 | 2.6% |
| gs2_80k | 3.6 | 13.3 | 5.4% | 2.6 | 9.2 | 2.4% |
| keep4k | 3.6 | 13.3 | 4.8% | 2.5 | 9.1 | 2.4% |

5kHz 付近（女性で 20 倍音前後）でも、中央値のずれは倍音の間隔の 4% ほど。録音に合わせる細かい分解能の loss が、ピッチのずれのせいで倍音を罰する状況ではない。

メモ: 最初の版の `--own-f0` は F0 を 1〜4kHz の comb が最大になるように選び、同じ帯域で測っていた。そのため 1〜4kHz の値が水増しされ、ピッチのずれも 12 cents と過大に出ていた。今の版で直してある。

### 2.3 学習データの高域の倍音

`scripts/m2/data_harmonicity.py`。各ソースから 150 クリップ（Emilia は 450）を取り、そのクリップ自身の有声フレームで comb と、1〜2.5kHz に対する帯域のレベルを測った。F0 が 165Hz 以上のフレーム（女性と高い声の男性）:

| ソース | フレーム | 4–6k comb | 6–8k comb | 4–6k レベル | 6–8k レベル |
|---|---:|---:|---:|---:|---:|
| JVS 女性（評価用） | 13,540 | 5.1 | 3.1 | −11.8 | −14.5 |
| Emilia HQ | 20,639 | 4.0 | 1.1 | −12.8 | −16.4 |
| Hi-Fi-CAPTAIN 女性 | 9,478 | 5.5 | 1.0 | −14.9 | −20.3 |
| JSUT（参考） | 7,858 | 4.4 | 1.2 | −11.4 | −13.5 |
| JVNV | 12,044 | 4.6 | 1.9 | −14.0 | −17.6 |
| あみたろ | 7,528 | 6.3 | 2.8 | −16.5 | −15.4 |
| JVS jvs001（男性、実音声） | 5,458 | 3.0 | 2.4 | −20.0 | −19.7 |
| Irodori（jvs001 を参照に合成） | 2,865 | 2.0 | 1.5 | −23.8 | −21.5 |

- 4〜6kHz の倍音は、どの自然音声のデータにも JVS のおよそ 8 割以上ある（Emilia HQ 78%、ほかは 9 割以上）。**採用版の学習データ（S3 + Emilia）に倍音が無かったから出せない、とは言えない**（S3 の半分は弱い可能性がある）。
- 6〜8kHz はあみたろ以外どれも弱い。JVS がむしろ強い側。6〜8kHz の倍音はデータの面でも難しい目標で、主目標は 4〜6kHz に置く。
- Irodori の合成（S3 と同じ系統）は、同じ話者の実音声より 4〜6kHz が約 4dB 暗く（6〜8kHz は 2dB）、倍音も 2/3。S3 の音声そのものはまだ測っていない（以前のフォルダにある）。

### 2.4 過学習プローブ: 今の構造で 4kHz 以上に倍音を作れるか

`scripts/m2/overfit_probe.py`。keep4k から、Hi-Fi-CAPTAIN 女性の 23 クリップ（2.5〜4.5 秒）だけを 4,000 step 学習（batch 8、LR 1e-4、識別器なし、1 本 3 分）。4kHz 以下は録音に対する mel、4kHz 以上は下の表の loss。評価は学習したクリップと、同じ話者の dev の 20 クリップ。録音の F0 で測った comb / 録音に対するレベル（dB）:

| | 学習 4–5k | 学習 5–6k | 未学習 4–5k | 未学習 5–6k |
|---|---:|---:|---:|---:|
| 録音 | 6.7 | 4.4 | 5.3 | 3.5 |
| 開始時（keep4k） | 3.1 / −6.8 | 1.2 / −6.6 | 2.5 / −6.7 | 0.4 / −6.1 |
| 残差層 1、高域は細かい STFT loss | 5.5 / −1.2 | 3.6 / −1.1 | 2.2 / −1.4 | 1.7 / −1.3 |
| 残差層 3、同上 | 5.6 / −1.1 | 3.5 / −1.1 | 2.4 / −1.2 | 1.8 / −1.0 |
| 残差層 1、高域は mel loss | 4.3 / −0.3 | 2.8 / −0.9 | **1.1** / −0.7 | 1.3 / −1.1 |

- 細かい分解能の STFT loss（`codec_ft.FineSpectrumLoss`）では、学習したクリップの 4〜6kHz に録音の 8 割の倍音が出る。**今の decoder の構造は 4kHz 以上の倍音を表現できる**。
- **残差層 3 は 1 と同じ到達点**（1,000 step 時点で少し速いだけ）。追加した 0.35M パラメータ（SEANet decoder 3.97M の 9%）は効いていない。
- 高域を mel loss にすると、レベルは録音まで上がるが、未学習のクリップの 4〜5kHz は 2.5 → 1.1dB に下がる。mel の帯域は高域で数百 Hz 幅で、倍音か雑音かを区別しないため、雑音で埋まる。gs2_80k と同じ現象を小さな規模で再現した。
- 細かい STFT loss でも、未学習のクリップでは 4〜5kHz が横ばい、5〜6kHz が 0.4 → 1.7dB。23 クリップでは汎化は限られる。全データで未知の話者にどこまで出るかは、まだ分からない（Phase 1 で調べる）。
- 4kHz 以下は、どの条件でも未学習のクリップで悪くなる（過学習のため。この試験の目的外）。

### 2.5 まとめ: 分かったこと / 分かっていないこと

分かったこと:

- 4kHz 以上の倍音が無いのは、ピッチのずれでも、decoder の表現力（構造・容量）でもない。採用版までの FT は高域を mel（倍音を見ない）か元の Mimi の出力（倍音が無い）に合わせていて、倍音を要求していなかった。ただし要求しても、全データでは汎化しなかった（次の項）。
- **全データで細かい STFT loss をかけた既存の `M2_fine4k` は、JVS に倍音を出していない**（以前のフォルダの再構成を今回の指標で測った）。元の Mimi から S3 + Emilia で 10k step、識別器なし。女性の有声 4–6kHz の comb 0.7dB（録音の F0）/ 0.8dB（出力自身の F0）、レベル −3.8dB（2,500 step 時点も 0.8dB / −4.0dB）。男性も 0.2dB。レベルが半分戻っただけで、中身は雑音。試聴で悪化とされたのと合う。同じ loss で過学習なら倍音が出る（§2.4）ので、**問題の中心は汎化**（多くの話者・文で、latent から高域の倍音を作れるように学ぶこと）にある。
- ほかの短い学習も同じ: `M2_keepW4k` 1.2dB / −7.0dB、`M2_gs2keepV4k` 1.2dB / −5.7dB（元の Mimi 1.2dB / −6.9dB）。

分かっていないこと:

- `M2_fine4k` との違い（出発点が keep4k、自然音声のみのデータ、識別器）で、未知の話者（JVS）に倍音が出るようになるか。出ない場合、原因がデータの多様さ（話者・声質）か、latent の情報か。
- 倍音を出した高域が、試聴で自然に聞こえるか（gs2_80k は数値が良くても不採用だった）。
- latent に、フレームごとの高域の倍音と雑音の比（息漏れの量など）の情報があるか。無ければ平均的な比でしか出せない。

## 4. Phase 1: 構造はそのまま、高域の学習目標を変える

一つずつ変えた 3 本。どれも keep4k から D-nat で 10k step。

| run | 4kHz 以下 | 4kHz 以上 | 識別器が見る帯域 | 共有スペクトル loss | H0 からの変更 |
|---|---|---|---|---|---|
| **H0**（対照） | 録音に対する mel | 元の Mimi の出力に対する mel（採用版と同じ） | 4kHz 以下 | 300–4000Hz | なし。新しいデータと識別器だけの効果を見る（keep4k とほぼ同じになるはず） |
| **H1** | 同上 | 録音に対する細かい STFT loss（`--high-mode fine`） | 4kHz 以下 | 300–4000Hz | 高域の目標 |
| **H2** | 同上 | 同上 | 全帯域 | 300–12000Hz | H1 に、識別器が高域も見る |

- H1 は過学習プローブの条件を全データにしたもの。H2 は、gs2_80k（全帯域の識別器 + 高域 mel）が雑音で埋めた条件と、高域の loss だけが違う。
- 1 本あたり 40 分（GPU を専有した場合。毎秒 4.5〜4.9 step、GPU メモリ 11GB）、評価に 20 分ほど。H1 と H2 を並行し、H0 は H1 の後。
- 監視の値で、1,000〜3,000 step のうちに 4–6kHz の comb が動くかを見る（過学習プローブでは 1,000 step で動いた）。`M2_fine4k` と同じくレベルだけが上がる場合は、10k を待たずに次の手を考える。

**Phase 1 の後の判断**

### 4.2 Phase 3 B1: 原音の F0 で正弦波の励振を足す（診断版）

`pocket_tts_ja/harmonic.py`。F0（WORLD の dio + stonemask、5ms）から、位相を累積した倍音の正弦波を帯域ごとに sin / cos で足し合わせ、帯域ごとのゲイン（decoder の transformer 出力から 1×1 畳み込み、ゼロ初期化）をかけて decoder の出力に加える。初期状態では keep4k と完全に一致する。`train_mimi_decoder.py --harmonic oracle`、`recon_jvs.py` は原音の F0 で復号する。

- **B1 v1（`M2H_B1o`、H2 の条件 + 励振、帯域 3–4.5 / 4.5–6 / 6–8 / 8–11kHz）**: JVS の監視値（高い声の 4–6kHz の comb / レベル）は、decoder の学習 500 step 後に **1.60 → 3.04dB**（−4.6dB）。H1 / H2 が 10k step で届かなかった値に一気に上がり、**位相のつながった励振があれば、未知の話者にも倍音を出せる**ことは確かめられた。ただしその後は 2.64 → 2.07 → 1.96dB（レベル −3.5 → −2.2dB）と下がり、decoder 自身の雑音が増えて励振を埋めていった。学習の高域の loss も H2 より高いまま（0.43 対 0.35）。3,181 step で止めた。2,500 step の JVS 1,000 件: 女性 4–6kHz 1.9 / −3.1dB、波形の相関 0.04。
- 考えられる原因: (1) 一番下の帯域（3–4.5kHz）が、decoder がすでに倍音を作っている 3–4kHz に重なる。(2) 帯域が 1.5〜3kHz と広く、帯域内のスペクトル包絡に合わせられない。(3) dio が有声区間の 5ms フレームの 8.6%（女性）を無声にし、そこでは励振が切れる。(4) decoder 自身の出力の高域に制約が無く、loss を下げる一番簡単な方法（雑音を足す）が残っている。
- **B1 v2（`M2H_B2o`）**: 帯域を 4kHz から 500〜1,500Hz 幅の 9 帯域に（境目で和が 1 になる縁）、dio の `allowed_range` 0.2 と 20ms までの無声の穴埋め（有声区間の取りこぼし 8.6% → 3.9%）、**decoder 自身の出力の 4kHz 以上を元の Mimi の出力に合わせる mel loss（`--noise-stock 15`）**。雑音は keep4k と同じ量に保ち、帯域を持ち上げられるのは励振だけにする（倍音 + 雑音の分解）。複数を同時に変えているので、効いた場合はどれが効いたかを後で切り分ける。

- **B1 v2 の結果（5k step、JVS 1,000 件）**: 女性の有声 4–6kHz の **comb 4.5dB / −3.0dB**（録音 4.7、keep4k 1.3、H2 1.7）。**1 周期後の相関は波形 0.14 / エンベロープ 0.59 で録音（0.15 / 0.60）とほぼ同じ**（keep4k 0.04 / 0.48）。倍音が欠けていた帯域で、波形の性質が録音並みになった。6–8kHz 1.0 / −3.2dB（録音 2.6）、男性 4–6kHz 1.8 / −3.0dB（録音 3.1、keep4k 0.5）。無声子音の 4–8kHz は −0.8 / −1.2dB（keep4k −6.0 / −6.8dB）で、雑音の制約をかけても摩擦音のレベルは録音並みに戻った（細かい STFT loss が引き上げた）。監視値は 10k に向けてまだ上がっている（5,500 step で 5.15dB / −2.0dB）。

### 4.3 試聴の結果（ユーザー、10/15 昼）と方針

- **H2 の方向は良い**（再構成の H2、生徒の TTS の `D1_6l_b@120k cfg1.0 M2H H2 t0.3`）。高域が立ちはじめ、元の Mimi より明るく聞こえる。**若干の機械音**がある気がする。
- **B2o / B4o / B5p（正弦波の励振）は不採用**。発音に同期したアーティファクトがかなり目立つ。数値（comb、1 周期後の相関）は録音並みだったが、聴感では悪い。励振の方向（Phase 3 B1、B6 を含む）はここで止める。
- 提案: 指標に neural MOS（UTMOS、UTMOSv2）を入れる。聴覚のモデルをある程度含むので、comb のような信号の指標が拾えない不自然さを拾える可能性がある。→ §4.4。

以後は H2 を基準にして、機械音を減らしつつ高域の明るさを保つ（または増す）条件を探す。

### 4.6 試聴の結果 3（ユーザー、10/16）: 機械音は 4kHz 以上の振幅にある

**m2h_noise の試聴**（jvs010_VOICEACTRESS100_081 が一番わかりやすい。H2g と録音を基準に）:
- どこに: 録音の 0–4kHz（0–2k、2–4k も）を H2g に替えても問題なし。**4kHz 以上を替えると H2g と同じ機械音**。4–8kHz だけだと少し違和感、8kHz 以上だけでも（4kHz 以上よりは少しまし）同じ機械音。
- 成分だけ: 「多い成分の 4kHz 以上」と「80ms 格子の模様」が主な成分らしい。倍音は「4kHz 以上の倍音の位置」。
- 振幅と位相: 差は微妙。「録音の振幅 + デコーダの位相」のほうが録音に近く、「デコーダの振幅 + 録音の位相」は全体にややノイジー → **機械音は振幅（スペクトル）にあり、位相ではない**。
- 誇張と除去: 格子の模様 ×4 はあまり強くならない。多い成分 ×3 のほうが機械音。**「多い成分を除く」でほぼ問題なし**。

**多い成分の中身**（女性 100 発話、4–12kHz、STFT 1024 / 5ms、3×3 で平滑した大きさの比較）:
- 対照として、録音の 4kHz 以上のスペクトログラムをそのまま使い、雑音の細かい構造だけを作り直した信号（セルごとに複素ガウスを掛ける、レベルを録音に合わせる）を置いた。
- 録音より多い成分は、録音の 4kHz 以上に対して H2 系 −9dB、keep4k −19dB（レベルが 6dB 低いぶん）、元の Mimi −18dB、対照 −31dB。対照より 20dB 大きく、雑音の細かい構造の違いでは説明できない。
- 時間: ラウドなフレームに録音と同じ割合で分布（録音の最大から −3dB 以内に 70%）。録音の谷を埋めているのではない。有声 71%、無声 29%。

**理由の見当**: H2 系は 4kHz 以上の mel loss を `FineSpectrumLoss`（1024 / 2048 点の窓のビンごとの L1）に替えた。窓が 43 / 85ms なので、10〜20ms の包絡は loss に入っていない（GAN だけが見ている）。keep4k は短い窓を含む mel loss で見ていたが、高域が 7dB 暗いので外れが目立たなかった。

**対策: `codec_ft.BandEnvelopeLoss`（`--w-env`、`--env-over`、`--env-band`）**: 4–11kHz の三角の 500Hz 帯域（足すと 1）の振幅の log10 の L1、STFT 256 / 512（hop 1/4）。セルは録音の帯域の平均の 1/100 まで数える。`--env-over` は decoder が録音より強いセルの重み。検証に `envover_*` / `envunder_*`（512 点、4–11kHz、録音より強い / 弱い分の平均 dB）を加えた。女性 40 発話: 元の Mimi 0.61 / 5.18dB、keep4k 0.56 / 5.17、H2 / H2g / H2gh 1.23〜1.25 / 3.22、H2g2 1.48 / 3.06。

### 4.9 指標の比較: ViSQOL と SCOREQ（10/17）

ユーザーの提案で、UTMOSv2 の代わり・補いになるかを JVS 再構成 1,000 件（ViSQOL は 0.6 秒の 1 件を除く 999 件）で調べた。どちらも両方の信号を 40Hz で high-pass。

- **ViSQOL v3**（google/visqol の pure Python 版 `visqol-python`、C++ 版と一致するとされる）: 録音との比較（full reference）。audio mode（48kHz に upsample、50Hz〜24kHz の gammatone 32 帯域の NSIM → SVR で MOS-LQO、録音同士で 4.73）。帯域ごとの類似度も出る（4〜8kHz に 5 帯域、8〜12kHz に 3 帯域。12kHz 以上は両方とも空）。1 件 0.2 秒。
- **SCOREQ**（`scoreq-pytorch`、fairseq なしの移植）: 16kHz の wav2vec 2.0。natural（NISQA で学習）/ synthetic（VoiceMOS 22）の no-reference と、録音との埋め込みの距離（ref）。

| decoder | UTMOSv2 | ViSQOL | NSIM 4–8k | NSIM 8–12k | SCOREQ nat | SCOREQ syn | SCOREQ ref（小さいほど良い） |
|---|---:|---:|---:|---:|---:|---:|---:|
| 録音 | 3.414 | 4.732 | 1 | 1 | 4.083 | 3.779 | 0 |
| 元の Mimi | 2.978 | 3.574 | 0.680 | 0.636 | 3.946 | 3.703 | 0.304 |
| gs2_80k（試聴で不採用） | 2.840 | **3.987** | 0.788 | 0.761 | **4.177** | 3.777 | 0.260 |
| keep4k | 3.014 | 3.543 | 0.672 | 0.619 | 4.106 | 3.725 | 0.264 |
| H2e（試聴で H2gh より悪い） | 3.197 | 3.972 | 0.793 | 0.763 | 4.134 | 3.841 | 0.226 |
| H2ex（同上） | 3.186 | 3.907 | 0.782 | 0.745 | 4.136 | 3.839 | 0.224 |
| H2gh | 3.268 | 3.938 | 0.778 | 0.752 | 4.123 | 3.803 | 0.223 |
| H2ghSG4（試聴で H2gh より良い） | 3.378 | 3.941 | 0.763 | 0.752 | 4.068 | 3.775 | 0.223 |

- **試聴の判断との一致**: UTMOSv2 は 3 つとも一致（gs2_80k < keep4k、H2e / H2ex < H2gh、H2ghSG4 > H2gh）。ViSQOL は gs2_80k を全 decoder で最高とし、H2e を H2gh より上（ファイルの 99% で）、H2ghSG4 は H2gh と同じ。SCOREQ synthetic は H2e / H2ex を上、H2ghSG4 を下とし、3 つとも逆。SCOREQ natural は keep4k と gs2_80k を録音より上とする。
- 録音を除く 17 decoder の平均の順位相関（UTMOSv2 と）: ViSQOL 0.18、NSIM 4–8k −0.38、SCOREQ syn −0.08、nat −0.6、ref 0.55（keep4k / 元の Mimi と H2 系の差による）。UTMOS22 は −0.86（GAN を強めるほど下がる）。
- **ViSQOL は録音との近さを測り、1 ファイルごとの揺れが小さい**（H2gh − keep4k は差 / 標準偏差 6.4、全ファイルで H2gh が上。UTMOSv2 は 1.2）。高域が足りない decoder（keep4k、元の Mimi）は 4〜12kHz の NSIM で大きく離れる。しかし高域を録音のレベルに合わせただけのもの（gs2_80k）や、包絡を合わせた H2e も高く出て、聴いた良さとは合わない。GAN を強めた H2ghSG4 の改善（裏のノイズが消えた）は見えず、4〜8kHz の NSIM はむしろ少し下がる。
- **結論**: 最大化する指標は UTMOSv2 hp40 のまま。ViSQOL は UTMOSv2 が見ない **8〜12kHz の歯止め**として `run_hf.sh` の最後に入れる（`visqol_eval.py`、H2gh との差。H2 系は 0.745〜0.763 で、keep4k は 0.619）。SCOREQ は使わない（16kHz で 8kHz 以上を見ず、試聴とも逆）。

**UTMOSv2 の安定性**: 1,000 件の平均は安定している。H2ghSG4 − H2gh は +0.111（95% 区間 ±0.012）、ファイルごとの差の標準偏差は 0.19、H2ghSG4 が上のファイルは 74%。6 文の平均で逆転する確率は約 7% で、試聴ページの 6 文はその側だった。

## 5. Phase 2: 容量（案 A）を同じ条件で比べる

Phase 1 の最良の条件で、残差層 1 と 3 を同じデータ・step・seed で比べる（1 本追加）。

- 残差層の追加は `codec_ft.expand_residual_layers`（追加した残差ブロックの最後の畳み込みをゼロにして恒等写像から始める）。確認済み: 追加直後の出力は追加前とビット単位で一致、フレームごとのストリーミング復号と一括復号の差は 1e-4（追加前と同じ水準）、保存と読み直しで一致。`load_decoder` はファイルの残差層の数に合わせて自動で拡張する。
- 過学習プローブでは差が無かったので、全データでも差が無ければ案 A はここで閉じる。差がある場合だけ、幅（`n_filters` 64 → 96、重みの移植が必要）を次の候補にする。
- 公開する場合の注意: 公式の loader は yaml の `seanet.n_residual_layers` を encoder と decoder の両方に使う。encoder にも恒等の残差ブロックを入れ、encode 結果が一致することを確かめてから配布物を作る。CPU 推論速度も測る。

Phase 1 で良い条件が見つかった場合は、この比較と並行して、学習の延長（30k〜50k step）と TTS での確認を行う。

## 6. Phase 3: 倍音の手がかりを持つ decoder（案 B、研究）

Phase 1 で JVS に倍音が出ない場合に進む。推論コードの変更を伴い、公式 wheel にはそのまま載らない。

1. **latent プローブ（B0）**: 32 次元・12.5Hz の latent（前後の文脈つき）から、200Hz 刻みの F0、有声 / 無声、4kHz 以上の倍音と雑音の比を予測する小さなネットを Emilia HQ で学習し、JVS で測る。F0 は今の decoder がすでに中央値 4 cents で再現しているので、焦点は倍音と雑音の比。
2. **正弦波の励振を足す（B1）**: F0 から作った倍音の正弦波（Nyquist を超える倍音は作らない）を、24kHz の段の入力に学習可能な 1×1 畳み込み（ゼロ初期化）で足す。NSF 系の最小の変更で、残りの構造と重みはそのまま使え、位相を累積するだけなのでストリーミングにも載る。**原音の F0 を与える診断版**を先に作り、効果があれば decoder の内部特徴から F0 を予測する版に進む。
3. **Wavehax / Vocos 系（B2）**: 複素スペクトログラムを生成して iSTFT で戻す方式。B1 で足りない場合だけ。

## 7. Phase 4: データと識別器（案 C）

Phase 1 の最良の条件に対して、一つずつ変える。

- **データ**: D-nat と Emilia HQ のみを比べる。6〜8kHz を狙うなら、倍音の強いあみたろの比率を変えた条件も候補（1 話者に偏る点に注意）。
- **識別器**: 全帯域の MS-STFT 識別器と、DAC 系の帯域別 multi-band multi-scale STFT 識別器を比べる。STFT の大きさを 2 の累乗の組み合わせ以外にする案（m2_idea.md の Stability AI の報告）も、線スペクトルが再発した場合の候補。
